# Этап 11 — Надёжность данных и эксплуатация

Закрывает **A-13, A-14, A-15, A-23**. Требования ТЗ v1.3: NFR-9, NFR-10, NFR-11.

## Зачем

После FR-14 БД панели перестала быть «кэшем метрик»: в ней лежат исходники
стеков и зашифрованный env. Их потеря невосполнима, а любое изменение схемы
без миграций ломает апгрейд с прода.

## Объём

### 11.1. Версионирование схемы (A-13, NFR-9)

- `PRAGMA user_version` как номер схемы; текущая существующая схема = версия 1.
- Список миграций `[]migration{Version, Apply(tx)}` в `internal/store/migrate.go`;
  при старте применяется всё, что новее, в одной транзакции на шаг.
- БД новее бинарника → панель не стартует с внятной ошибкой (защита от отката).
- Тесты: чистая БД → последняя версия; БД версии N → доводится до N+1;
  БД из будущего → ошибка.

### 11.2. Резервная копия БД (A-14, NFR-10)

- `POST /backup` — онлайн-снимок через `VACUUM INTO` во временный файл,
  отдача файлом (`Content-Disposition`), удаление временного файла.
- Только admin, CSRF, запись в audit (`backup.create`).
- Раздел в README: как забирать бэкап и что в нём (в т.ч. что env зашифрован
  и без `DSMS_ENCRYPTION_KEY` бэкап бесполезен — ключ хранить отдельно).
- Кнопка «Скачать резервную копию» на экране Settings.

### 11.3. Версия сборки (A-15, NFR-11)

- `-ldflags "-X main.version=... -X main.commit=..."` в обоих Dockerfile,
  значения из git-тега/SHA (в CI — из `github.ref_name`/`github.sha`).
- `GET /healthz` → `{status, version, commit}`.
- Фронт берёт версию из `/healthz`, а не только из `package.json`;
  в шапке показывается версия бэкенда, при расхождении с бандлом — подсказка
  «обновите страницу» (это и была исходная проблема с кэшем).

### 11.4. Хелсчеки в stack file (A-23)

- `healthcheck` для panel (`/api/v1/healthz`) и agent (`:9001/healthz`)
  в `dsms.yml`, разумные `interval`/`retries`/`start_period`.

## Порядок работ

1. `internal/store/migrate.go` + перевод существующей схемы в миграцию №1.
2. Тесты миграций (три сценария выше).
3. Бэкап: эндпоинт + audit + кнопка в Settings + i18n.
4. Версия: ldflags, `/healthz`, фронт.
5. Хелсчеки в `dsms.yml`, проверка, что Swarm их принимает.

      исходники стеков. (`TestBackupTo`, `api/backup_test.go: TestBackupDownload` —
      проверяется сигнатура файла SQLite и запись в audit)
- [x] `/healthz` отдаёт версию, commit и версию схемы; в UI видна версия бэкенда,

- [x] `go build ./... && go vet ./... && go test ./...` зелёные в panel и agent;
      `npm run build` чист.
- [ ] `docker stack deploy` с новым `dsms.yml` проходит, хелсчеки зелёные.
