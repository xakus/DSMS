# Этап 6 — In-app алерты

Покрывает FR-12. Внешние каналы (Telegram) — v2, но интерфейс канала
доставки закладывается подключаемым.

## Backend

1. Движок правил: оценка на каждом ingest-батче и docker-событии
   - disk used > 90% (порог из settings)
   - нода down / агент молчит > 60с
   - desired > running дольше N сек
   - task non-zero exit
2. Состояния: active → resolved; активные — в памяти,
   журнал — в таблице alerts (SQLite)
3. Доставка: WS topic `alerts` + `GET /alerts` (активные + история)
4. Интерфейс Notifier (v2: Telegram/email реализуют его)

## Frontend

1. Колокольчик в шапке: счётчик активных, dropdown последних
2. Экран Alerts: активные + журнал, фильтры по типу/ноде/сервису
3. Тосты на новые critical-алерты

## Критерии проверки

- [ ] go test: правило срабатывает/резолвится на синтетических метриках
- [ ] go test: повторный батч не плодит дубликаты активного алерта
- [ ] UI: алерт приходит по WS без перезагрузки
