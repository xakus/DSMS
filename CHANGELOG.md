Ссылки на требования — по номерам из [технического задания](dsms-tz-v1.md)

## [2.3.0] — 25.11.2026

Этап 15 (ТЗ v1.5, план — `docs/plans/stage-15-live-tables-honest-prune.md`).
**Панель и агентов обновлять вместе:** новый расчёт очистки и признак
`tasks_state` — на стороне агента.

### Добавлено

- **FR-11. «Очистить всё»** (3.11.6): полная очистка ноды одной кнопкой в
  правильном порядке — контейнеры, образы, кэш сборки, анонимные тома.
- **FR-04. Причина прочерка** (3.4.7): у сервиса и задачи без метрик в подсказке
  видно, с какой ноды нет данных и почему — агент молчит, агент старой версии,
  агент не смог опросить Docker, задача только что запущена. API: поле `no_data`.
- Таблица задач сервиса: колонка «Образ» — видно, какая задача на какой версии.

### Изменено

- **Таблицы сервисов, стеков и задач не «прыгают»** (6.4): ширины колонок и
  высота строк не зависят от цифр; на широком мониторе свободное место делится
  между колонками, а не достаётся одной колонке «Имя».
- Таблицы обновляются с интервалом метрик из настроек (раньше — раз в 5 с).
- Реплики: работает больше задач, чем нужно (например, 9 из 3) — жёлтая метка с
  пояснением, а не зелёная.

### Исправлено

- **FR-11. Оценка «освободится» совпадает с результатом очистки** (3.11.5).
  Раньше складывались полные размеры неиспользуемых образов: общий слой считался
  много раз, слой работающего образа — тоже, а именованные тома, которые очистка
  не трогает, входили в оценку. На экране было «несколько ГБ», освобождалось в
  разы меньше. Теперь образы считаются по слоям, слои в кэше сборки и образы под
  остановленными контейнерами показаны отдельно, тома — только анонимные.
- **FR-11.** Кнопка очистки активна, когда есть что удалять, даже если сразу
  освободится 0 байт (остановленный контейнер без данных держит свой образ).
- **FR-04. Прочерки больше не мигают** (3.4.7): один сбой опроса Docker или батч
  от агента старой версии на той же ноде стирал цифры всех её сервисов.
- **Агент:** контейнер, чей cgroup не найден на хосте, больше не пропускается —
  цифры берутся у Docker; добавлена раскладка cgroup v1 + systemd; зависший
  Docker не останавливает сбор метрик ноды (предел ожидания 10 с).

## [2.2.0] — 25.11.2026

Этап 14 (ТЗ v1.4, план — `docs/plans/stage-14-stack-control-service-usage.md`).
**Панель и агентов обновлять вместе:** потребление сервисов считает новый агент.
В `dsms.yml` образы закреплены точной версией вместо `latest`.

### Добавлено

- **FR-08. Остановить / запустить стек целиком** (3.8.3): кнопки на экране
  «Стеки» и на странице стека. Остановка = 0 реплик каждому сервису с
  запоминанием прежнего числа, запуск возвращает как было. Global-сервисы
  пропускаются с явным сообщением. API: `POST /stacks/{name}/stop`, `/start`.
- **FR-08. Страница стека** (3.8.2): сервисы стека с потреблением, сети, тома,
  secrets и configs (свои и внешние), все действия над стеком.
- **FR-04. Потребление сервисов** (3.4.7): ноды размещения, CPU, RAM и скорость
  сети (приём/отдача) — по каждой задаче и суммарно по сервису и стеку, с
  сортировкой «кто грузит кластер». Агент шлёт метрики по каждой задаче Swarm
  (поле `tasks` батча); на панели хранится только последнее значение.
- **FR-04. Полная спецификация сервиса** (3.4.4): digest образа, команда, сети,
  порты, тома, лимиты и резервы, политика перезапуска и обновления, secrets,
  configs, healthcheck, labels.
- Сводка групповых операций над стеком (3.8.6): что сделано, что пропущено и
  почему, что упало — с именами сервисов и текстом ошибки.

### Исправлено

- **Стек из файла: сервисы не находили друг друга по именам из compose**
  (`web`, `db`) — не ставился сетевой псевдоним, который ставит
  `docker stack deploy` (3.14.5). Уже развёрнутые стеки исправляются
  передеплоем из файла.
- **Сеть ноды показывала трафик агента, а не ноды:** счётчики читались из
  сетевого пространства контейнера агента. Теперь — из пространства ноды, и
  только по аплинкам (без veth и мостов Docker, которые завышали сумму).
- **Ложные алерты `task_failed`** при штатной остановке контейнера (Stop, деплой,
  scale-down дают код 137/143): алерт только если задача Swarm упала сама (3.12.1).
- **Удаление стека** убирает и его сети, secrets, configs (раньше — только
  сервисы); managed-стек без живых сервисов теперь удаляется (раньше — `404` и
  стек оставался в списке навсегда); ошибка на одном сервисе не обрывает
  удаление и попадает в audit.
- **Имя стека** проверяется до сохранения исходника (3.14.13): имя вроде `a?b`
  оставляло в базе стек, который нельзя ни развернуть, ни удалить.
- **RAM контейнеров** считается без неактивного файлового кэша, как в
  `docker stats` (раньше база данных «занимала» гигабайты кэша).
- Redeploy / Deploy стека при сбое называют упавшие сервисы (раньше —
  `502 some services failed`).
- Запись «сервис остановлен панелью» больше не остаётся после неудачной
  остановки и после передеплоя стека из файла.
- UI: остановленный стек не красится красным; значок «идёт обновление» не
  горит вечно после завершённого обновления; таблицы не мигают при опросе и не
  сыплют тостами при недоступной панели; тосты переведены; иконки вместо эмодзи
  на странице сервиса; у кнопок-иконок есть подписи для скринридера; на
  экранах уже 1440 px редкие действия сервиса убраны в меню «ещё», чтобы
  CPU/RAM/сеть были видны без прокрутки.

### Изменено

- Ответ `POST /stacks/{name}/redeploy`, `/deploy` и `DELETE /stacks/{name}` —
  всегда `200` со сводкой `done / skipped / failed / resources` вместо
  `502` без подробностей. Клиентам API: проверяйте `failed`.
- `/services`, `/services/{id}`, `/stacks`, `/stacks/{name}` — новые поля
  `nodes`, `usage`, `stopped`, `stoppable` и расширенная `spec`.
- Интервал опроса списков сервисов и стеков — 5 с (было 10 с).

## [2.0.0] — готовится

### Добавлено

- **FR-14. Деплой стека из compose-файла через UI** — то, что раньше делалось
  только через `docker stack deploy`:
  - загрузка YAML (вставкой или файлом) + переменные окружения (`.env` и
    ручные пары), интерполяция `${VAR}` / `${VAR:-default}`, YAML-якоря;
  - исходник хранится в панели (env шифруется AES-GCM) — стек можно открыть,
    отредактировать, скачать и передеплоить одной кнопкой;
  - валидация до деплоя: что будет создано/обновлено/удалено, отсутствующие
    `external`-ресурсы и список полей, которые не переносятся в Swarm;
  - `prune` (удаление сервисов, ушедших из файла) — только по явному согласию.
- Поддержка в конвертере: `volumes` (именованные, bind, tmpfs, driver_opts),
  `secrets`/`configs`, `healthcheck`, `logging`, `ulimits`, `sysctls`,
  `cap_add/drop`, `dns`, `user`, `working_dir`, `hostname`, `stop_grace_period`,
  `platform`, `deploy.endpoint_mode`, `placement.preferences` и
  `max_replicas_per_node`, `rollback_config`.
- **Резервная копия БД** (NFR-10): онлайн-снимок через `VACUUM INTO`,
  кнопка в Settings, запись в журнал действий.
- **Версия сборки** (NFR-11) в `GET /healthz` и в шапке интерфейса;
  расхождение версий фронта и бэкенда подсвечивается (это почти всегда кэш браузера).
- **Хелсчеки** для panel и agent в `dsms.yml` и в образах: пробой служит сам
  бинарник (`-healthcheck`), потому что в scratch нет curl/wget.
- Статический анализ и тесты в CI: `golangci-lint`, `eslint`, `vitest`,
  автоматическая проверка размеров образов (NFR-12).

### Изменено

- **Схема БД версионируется** (NFR-9): миграции применяются при старте,
  ручных действий при обновлении не требуется. Панель откажется стартовать
  на базе от более новой сборки — защита от потери данных при откате.
- Сводка деплоя разделена: отдельно сервисы, отдельно созданные сети и
  secrets/configs.

### Исправлено

- **Обход ограничения попыток входа.** Адрес клиента брался из левого элемента
  `X-Forwarded-For`, который подделывается — перебор пароля не упирался в лимит.
  Теперь берётся правый элемент, который дописывает reverse proxy.
- **Ошибка 500 на странице сервиса** без `deploy.placement`.
- **Логи сервиса могли перестать открываться**: завершившийся стрим не
  удалялся из реестра и следующий запуск считал его работающим.
- Мусорные значения в compose-файле (`replicas: -1`, некорректные `mode` и
  `retries`) больше не превращаются в абсурдные величины.
- Закрыты 2 уязвимости в npm-зависимостях (nanoid, postcss).

### Безопасность

- Ограничение размера загружаемого стека — 1 МБ (ТЗ 3.14.11).
- Label `com.docker.stack.namespace` ставится на все создаваемые панелью
  объекты (сети, secrets, configs, тома) — иначе они не опознаются как часть
  стека при удалении.

## [1.0.0] — готовится

Первая полная версия панели: замена устаревшим Swarmpit и Portainer CE.

### Добавлено

- **FR-01…FR-03.** Дашборд кластера, страница ноды с живыми метриками
  (CPU/RAM/диск/сеть, графики uPlot), управление нодами: promote/demote,
  drain/pause, labels, join-токены, удаление. Защита от потери кворума.
- **FR-04.** Управление сервисами: scale, stop (с запоминанием числа реплик),
  start, redeploy (`ForceUpdate`), deploy (подтягивание свежего образа по тегу),
  смена образа, rollback, удаление.
- **FR-05.** Стриминг логов по WebSocket + постраничная история, различимые
  реплики, фильтры.
- **FR-06.** Лента событий Docker и журнал действий (audit).
- **FR-08.** Управление стеками целиком: группировка по label, redeploy и
  deploy всего стека.
- **FR-09…FR-11.** Secrets (неизвлекаемые) и configs, сети и тома,
  disk usage и prune по нодам.
- **FR-12.** In-app алерты: диск, молчащий агент, деградировавший сервис,
  упавшая задача. Доставка по WebSocket, канал проектировался подключаемым.
- **FR-13.** Учётные данные приватных реестров, пароли шифруются AES-GCM.
- **FR-07.** Аутентификация: сессии в HttpOnly/Secure/SameSite-cookie, bcrypt
  cost 12, CSRF на мутирующие запросы, ограничение попыток входа с backoff,
  защитные заголовки (CSP, X-Frame-Options, nosniff).
- История метрик в SQLite: минутные агрегаты с настраиваемой ретенцией,
  восстановление 15-минутного окна после рестарта панели.
- Интерфейс: Vue 3 + Naive UI, тёмная и светлая темы, i18n (EN/RU),
  адаптивная вёрстка. Собирается в бинарник панели через `go:embed`.
- Агент: метрики хоста и контейнеров, серверный интервал сбора, буферизация
  при недоступности панели.
- Multi-arch образы (amd64 + arm64) в ghcr.io, сборка в GitHub Actions.
